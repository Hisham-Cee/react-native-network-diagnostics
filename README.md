# react-native-network-diagnostics

Network health diagnostics for React Native. It tells you **how healthy the connection
is and why networking might be failing**: whether the OS validated internet access,
whether a captive portal is in the way, whether the network is metered or in Low Data
Mode, and how long DNS, TCP, TLS and a full HTTPS request to **your own backend** take,
with failures normalized into clear error codes.

> **Status: experimental (0.1.x), not yet published to npm.** The API may change in minor
> versions.
>
> - **Android:** built (debug and release) and tested on a physical device with React
>   Native 0.86.2. Wi-Fi, cellular, offline, endpoint timeout, DNS failure, TLS failure
>   and network monitoring behave as documented. Kotlin unit tests pass under Gradle.
>   Captive-portal detection has **not** been tested on a real captive-portal network.
> - **iOS:** implemented but **not yet built or tested**.
>
> Details: [docs/MANUAL_TESTING.md](docs/MANUAL_TESTING.md) and
> [docs/FINAL_IMPLEMENTATION_AUDIT.md](docs/FINAL_IMPLEMENTATION_AUDIT.md).

## Why this package exists

[`@react-native-community/netinfo`](https://github.com/react-native-netinfo/react-native-netinfo)
answers _"what network are we connected to?"_. This package answers a different question:
_"is the connection usable, and if not, what is wrong?"_. It complements NetInfo; keep
using NetInfo for SSID, cellular generation or signal strength.

| Question                                             | NetInfo                        | This package                           |
| ---------------------------------------------------- | ------------------------------ | -------------------------------------- |
| Connected? Wi-Fi or cellular?                        | Yes                            | Yes (minimal)                          |
| Did the OS validate internet access? Captive portal? | Partly (`isInternetReachable`) | Android OS signals; `undefined` on iOS |
| Metered? Low Data Mode / Data Saver?                 | `isConnectionExpensive`        | `metered` and `constrained`            |
| Can I reach **my** API, and how fast?                | No                             | Yes                                    |
| Is it DNS, TLS, a timeout or no route?               | No                             | Normalized error codes                 |
| DNS / TCP / TLS timings                              | No                             | Yes, both platforms                    |

Details: [docs/COMPETITIVE_ANALYSIS.md](docs/COMPETITIVE_ANALYSIS.md).

## Installation

```sh
npm install react-native-network-diagnostics
# or
yarn add react-native-network-diagnostics
```

iOS:

```sh
cd ios && pod install
```

Then rebuild the app. Expo: requires a [development build](https://docs.expo.dev/develop/development-builds/introduction/)
(`npx expo prebuild` / `expo run:*`); it cannot work in Expo Go. Expo has not been tested.

## Requirements

|              | Minimum                                                                                                      |
| ------------ | ------------------------------------------------------------------------------------------------------------ |
| React Native | 0.80, **New Architecture enabled** (default since 0.76, mandatory since 0.82). Only 0.86.2 has been tested.  |
| iOS          | React Native's minimum (15.1)                                                                                |
| Android      | API 24 (React Native's minimum)                                                                              |
| Web          | Not supported. react-native-web has no `TurboModuleRegistry`, so importing the package in a web build fails. |

No runtime permission prompts. Android uses the install-time `ACCESS_NETWORK_STATE` and
`INTERNET` permissions, which the library declares. iOS needs none.

## New Architecture

The module is a TurboModule generated by React Native Codegen from a TypeScript spec.
Android is Kotlin; iOS is Swift behind a thin Objective-C++ adapter (required to conform
to the generated protocol). There is no legacy bridge implementation and no C++.
See [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md).

## Basic usage

```ts
import { getNetworkDiagnostics } from 'react-native-network-diagnostics';

// OS state only. Sends no network request.
const state = await getNetworkDiagnostics();

// Probe your own health endpoint.
const result = await getNetworkDiagnostics({
  endpoint: 'https://api.example.com/health',
  timeoutMs: 5000,
});

console.log(result.quality); // 'excellent' | 'good' | 'fair' | 'poor' | 'offline' | 'unknown'
console.log(result.latency.httpsMs); // e.g. 84
console.log(result.endpoint?.error); // e.g. { code: 'DNS_FAILURE', message: '...' }
```

Example result on Android Wi-Fi:

```js
{
  connected: true,
  type: 'wifi',
  vpn: false,
  internet: { validated: true, captivePortal: false },
  conditions: { metered: false, constrained: false },
  endpoint: {
    url: 'https://api.example.com/health',
    reachable: true,
    statusCode: 200,
    latencyMs: 84,
    samples: 1,
    successfulSamples: 1,
  },
  latency: { httpsMs: 84, dnsMs: 6, tcpConnectMs: 21, tlsHandshakeMs: 34 },
  quality: 'excellent',
  timestamp: 1791360000000,
}
```

On iOS, `vpn`, `internet.validated` and `internet.captivePortal` are `undefined` because
iOS has no public API for them.

### Explaining a failure to the user

```ts
const { endpoint, internet, connected } = await getNetworkDiagnostics({
  endpoint,
});

if (!connected) return 'You are offline.';
if (internet.captivePortal) return 'Sign in to this Wi-Fi network first.';
if (endpoint && !endpoint.reachable) {
  switch (endpoint.error?.code) {
    case 'DNS_FAILURE':
      return 'Our server name could not be resolved.';
    case 'TLS_FAILURE':
      return 'A secure connection could not be made. Public Wi-Fi may require sign-in.';
    case 'TIMEOUT':
      return 'The connection is too slow right now.';
    case 'CONNECTION_FAILURE':
      return 'Our server could not be reached.';
  }
}
```

## Hook

```tsx
import { useNetworkDiagnostics } from 'react-native-network-diagnostics';

function NetworkBadge() {
  const { diagnostics, loading, error, refresh } = useNetworkDiagnostics({
    endpoint: 'https://api.example.com/health',
  });

  if (loading && !diagnostics) return <Text>Checking...</Text>;
  if (error) return <Text>{error.code}</Text>;
  return <Text onPress={refresh}>{diagnostics?.quality}</Text>;
}
```

The hook runs once on mount and then only when you call `refresh()`. It never polls.
Monitoring is opt-in:

```ts
useNetworkDiagnostics({ endpoint, monitor: true }); // re-runs ~1 s after OS network changes
```

Passive listener without the hook:

```ts
import { addNetworkStateListener } from 'react-native-network-diagnostics';

const unsubscribe = addNetworkStateListener((state) => console.log(state.type));
unsubscribe();
```

## API reference

| Export                                                                                   | Description                                                |
| ---------------------------------------------------------------------------------------- | ---------------------------------------------------------- |
| `getNetworkDiagnostics(options?)`                                                        | OS state plus optional endpoint probe, latency and quality |
| `getNetworkState()`                                                                      | OS state only, no network traffic                          |
| `addNetworkStateListener(listener)`                                                      | Passive change listener; returns unsubscribe               |
| `useNetworkDiagnostics(options?)`                                                        | React hook: `{ diagnostics, loading, error, refresh }`     |
| `classifyNetworkQuality(input, thresholds?)`                                             | Pure quality classifier                                    |
| `classifyLatency(ms, thresholds?)`, `DEFAULT_QUALITY_THRESHOLDS`                         | Latency buckets                                            |
| `NetworkDiagnosticsError`, `isNetworkDiagnosticsError`, `NETWORK_DIAGNOSTIC_ERROR_CODES` | Errors                                                     |

Full reference with all types: [docs/API.md](docs/API.md).

## Configuration

| Option                     | Default               | Notes                                                   |
| -------------------------- | --------------------- | ------------------------------------------------------- |
| `endpoint`                 | none                  | Absolute `https://` URL. Without it no request is sent. |
| `timeoutMs`                | `5000`                | 500 to 60000, per request                               |
| `method`                   | `'HEAD'`              | or `'GET'`; the response body is never downloaded       |
| `samples`                  | `1`                   | 1 to 5; medians reported; stops at first failure        |
| `qualityThresholds`        | `150 / 400 / 1000` ms | `{ excellentMs, goodMs, fairMs }`                       |
| `runOnMount` (hook)        | `true`                |                                                         |
| `monitor` (hook)           | `false`               |                                                         |
| `monitorDebounceMs` (hook) | `1000`                |                                                         |

Use an endpoint that is cheap for your server: a static health check that answers `HEAD`
with 200 or 204, without authentication.

## How quality is calculated

1. Not connected, or the OS reports a captive portal: `offline`.
2. A probe was made and failed: `poor`.
3. A probe succeeded: by `latency.httpsMs`: below 150 ms `excellent`, below 400 ms
   `good`, below 1000 ms `fair`, otherwise `poor`.
4. No probe, Android says not validated: `poor`.
5. Otherwise `unknown`: nothing was measured.

`httpsMs` is measured on a **fresh** connection (DNS + TCP + TLS + server time, about
three round trips), so it is larger than a ping. The thresholds are heuristics explained
in [docs/API.md](docs/API.md#quality-classification); override them for your backend.
HTTP status codes do not affect quality: a 500 proves the network path works.

## Limitations

- **Latency only.** No bandwidth, throughput, jitter, packet loss or ICMP ping.
- One sample is noisy. Use `samples: 3` when the number matters; it triples the requests.
- `httpsMs` includes your server's response time. A slow endpoint looks like a slow network.
- `dnsMs` may be near zero when the OS resolver cache answers.
- On Android, `httpsMs` includes any time the request waits in OkHttp's queue (negligible
  unless many probes run at once).
- Probes use the package's own HTTP client, not your app's networking stack, so your
  interceptors, certificate pinning and proxy settings are not exercised.
- Right after a network switch, Android may briefly report `validated: false` while it
  re-validates.
- iOS cannot report OS internet validation, captive portals or VPNs. A probe is the only
  reliable check there.
- Android Data Saver changes are seen on the next read or network event, not instantly.
- In-flight native requests are not cancelled when a component unmounts; they finish
  within `timeoutMs` and the result is ignored.
- Only `https://` endpoints. Plain HTTP is rejected.
- Requires the New Architecture and React Native 0.80+.
- Android has been tested on one physical device only; captive portal, VPN, metered
  Wi-Fi, Data Saver and API 24/25 are not yet verified. iOS has not been built or tested.
  See the [manual test matrix](docs/MANUAL_TESTING.md).

## Privacy

- **No default endpoint.** Without `endpoint`, the package makes **no network request**.
- With `endpoint`, it sends 1 to 5 `HEAD` (or `GET`) requests to **that URL only**, with
  no cookies, cache, stored credentials or body. Redirects are not followed and response
  bodies are not read.
- No telemetry. Nothing is sent to the package authors or any third party.
- No packet inspection, no access to other apps' traffic, no browsing history.
- No location or runtime permissions.

## Troubleshooting

| Symptom                                                   | Cause and fix                                                                                                                               |
| --------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------- |
| `DIAGNOSTIC_UNAVAILABLE` "native module is not available" | Rebuild the app after installing; run `pod install`; use a development build instead of Expo Go; make sure the New Architecture is enabled. |
| `INVALID_ENDPOINT`                                        | The endpoint must be `https://host/...` with no credentials or spaces.                                                                      |
| `TLS_FAILURE` on public Wi-Fi                             | Probably a captive portal. On Android check `internet.captivePortal`.                                                                       |
| `TLS_FAILURE` everywhere                                  | Server certificate problem, certificate pinning or a TLS-inspecting proxy.                                                                  |
| Always `TIMEOUT`                                          | Endpoint does not answer `HEAD`? Try `method: 'GET'`. Increase `timeoutMs` on slow networks.                                                |
| `quality: 'unknown'`                                      | No endpoint was given, so nothing was measured.                                                                                             |
| `statusCode: 405`                                         | Your server rejects `HEAD`. Quality is still computed; use `method: 'GET'` if you prefer.                                                   |
| iOS fields are `undefined`                                | Expected. See Platform support.                                                                                                             |
